# Copybara 🦫

A tiny personal tool that mimics **Universal Clipboard in one direction:
computer → iPad**, for when Handoff/Continuity is blocked (e.g. by MDM).

Copy anything on a **Mac** or **Windows** PC — styled text, code, images — and it
lands on the iPad clipboard. You just paste (e.g. into GoodNotes). The iPad app is
the same for both; each computer runs a small sender.

## How it works

- **Mac** runs a menu-bar agent that watches the clipboard and pushes every
  change over the local Wi-Fi network, **encrypted**.
- **iPad** runs an app that advertises itself on the network (Bonjour), receives
  each change, and writes it to the iPad clipboard.
- iOS only lets an app write the general clipboard while it is the **active
  (foreground) app** — a backgrounded app gets "Pasteboard is not available at
  this time". So Copybara does **not** try to run in the background (no battery
  drain, no audio); iOS suspends it normally. It **buffers** the latest clip and
  applies it when active:
  - **Best workflow:** keep Copybara in **Split View next to GoodNotes**. In
    Split View both apps are active at once, so Mac copies land on the clipboard
    automatically — just paste.
  - Otherwise: tap into Copybara (it applies the latest clip on becoming active,
    or tap the **Apply** button), then switch back and paste.
- When Copybara becomes active again after being suspended, it reconnects and the
  Mac **re-pushes the current clipboard**, so the latest copy is always there.
- Everything is encrypted with a key derived from a shared secret, so only your
  two devices can talk. Nothing leaves your Wi-Fi network.

## Honest limitations (please read)

- **Mac → iPad only.** (Reading the iPad clipboard in the background is
  impossible for third-party apps, so the reverse direction isn't built.)
- **The clipboard write only happens while Copybara is active/foreground**
  (Split View counts). Clips received while it's backgrounded are held until it
  next becomes active. This is an iOS restriction, not a bug.
- **Same Wi-Fi only** for now. Cross-network ("any Wi-Fi") is possible later by
  adding a small self-hosted relay — the design already anticipates it.
- **Free Apple ID** signing expires every ~7 days — after that the iPad app
  won't launch until you re-install it (see [Weekly re-sign](#weekly-re-sign-free-apple-id)).
  This is an Apple rule, not something code can change. A paid Developer account
  ($99/yr) makes it 1 year.

## One-time setup

### 0. Generate the Xcode projects (fresh clone)

The `.xcodeproj` files are generated by [XcodeGen](https://github.com/yonyz/XcodeGen)
and git-ignored, so after cloning:

```bash
brew install xcodegen   # once
cd copybara/mac && xcodegen generate
cd ../ios && xcodegen generate
```

### 1. Pick your own secret (both apps)

Edit `sharedSecret` in **both** files to the same private phrase, so only your
devices can talk:

- `mac/Sources/Protocol.swift`
- `ios/Sources/Protocol.swift`

(Editing source needs no project regen. Only re-run `xcodegen generate` in a
folder if you change its `project.yml`.)

### 2. Install the iPad app (from Xcode, first time)

```bash
open copybara/ios/Copybara.xcodeproj
```

In Xcode:
1. Select the **Copybara** scheme and your iPad (**copper m4**) as the run target.
2. Signing & Capabilities → Team → your Apple ID (already set to team `99V875JU84`).
3. Press **Run** (⌘R).
4. On the iPad, first launch only: Settings → General → VPN & Device Management →
   trust your developer certificate, then reopen the app.
5. Tap **Allow** on the Local Network prompt.

### 3. Install the Mac agent

Build it and copy it to /Applications so it lives in a stable place:

```bash
cd copybara/mac && xcodebuild -project CopybaraMac.xcodeproj -scheme CopybaraMac \
  -configuration Debug -derivedDataPath build build
cp -R build/Build/Products/Debug/Copybara.app /Applications/
open /Applications/Copybara.app
```

A 🦫 clipboard icon appears in the menu bar. Tap **Allow** on the Local Network
prompt. When it finds the iPad, the icon fills in and the menu says
"Connected to iPad".

### 4. (Recommended) Make the Mac agent auto-start at login

So a Mac restart doesn't need you to reopen it, install the login item
(a LaunchAgent that opens Copybara once at each login):

```bash
copybara/scripts/login-item.sh install
```

Remove it anytime with `copybara/scripts/login-item.sh uninstall`. (Prefer the
GUI? System Settings → General → Login Items → + → `/Applications/Copybara.app`
does the same thing.)

### 5. Test it

Put Copybara in Split View next to GoodNotes on the iPad. Copy text or an image
on the Mac → paste in GoodNotes.

## Daily use

1. On the iPad, keep **Copybara in Split View beside GoodNotes** (drag Copybara
   from the dock to the side of the screen).
2. Copy anything on the Mac.
3. Paste in GoodNotes. That's it.

The Mac menu-bar item shows connection status, the last item sent, a toggle to
pause syncing, and a "Send current clipboard now" button.

## After a restart / reconnecting

Nothing here needs re-installing — just re-opening. Discovery and reconnection
are automatic once both apps are running on the **same Wi-Fi**.

### If you restart the **Mac**
- If you added Copybara to **Login Items** (setup step 4): nothing to do — it
  starts automatically and reconnects to the iPad.
- If you did **not**: reopen it once — `open /Applications/Copybara.app` (or
  Spotlight → "Copybara"). It rediscovers the iPad on its own.

### If you restart the **iPad**
- iOS never auto-launches third-party apps after a reboot, so **tap the Copybara
  icon once** to open it, then put it back in Split View beside GoodNotes.
- No trust/re-install needed (the signature is still valid until its ~7-day
  expiry). The Mac reconnects automatically once the app is open.

### If Wi-Fi changes / it seems disconnected
- Make sure **both devices are on the same Wi-Fi network**.
- The Mac keeps searching and reconnects by itself. If it looks stuck, either
  toggle **"Sync clipboard to iPad"** off/on in the menu, or bring Copybara to
  the front on the iPad (that re-advertises it and forces a fresh connect).
- Networks with **AP/client isolation** (some guest or corporate Wi-Fi) block
  device-to-device traffic — discovery may show but the connection won't
  complete. Use a normal home/personal network, or wait for the relay (below).

### After ~7 days (app won't open on iPad)
See [Weekly re-sign](#weekly-re-sign-free-apple-id).

## Windows → iPad

The iPad app is identical; Windows just runs a small Python sender that speaks the
same encrypted protocol. **No admin rights needed**, and everything is **isolated
to its own folder** (a local `.venv`) so it can't affect other scripts.

Requirements on the PC: **Python 3** (`python --version` should work) on the
**same Wi-Fi** as the iPad.

### Install (once)

1. Copy the contents of `windows/` into your target folder, e.g.
   `C:\Users\vinayd\VDesktop\CCFD_PROD\Scripts\Copybara`.
2. Make sure `SHARED_SECRET` in `copybara_win.py` matches the value in the
   Mac/iPad `Protocol.swift`.
3. Double-click **`setup.bat`**. It creates `.venv` inside the folder and installs
   `cryptography pywin32 pillow zeroconf` there — nothing global, nothing shared.

### Run / control (batch files, with feedback)

| File | What it does |
|------|--------------|
| `start.bat` | Starts the sender in the background; prints its PID; refuses to double-start. |
| `stop.bat`  | Stops it (by PID). |
| `status.bat`| Shows **RUNNING/STOPPED** + the last dozen log lines (and any errors). |
| `run-console.bat` | Runs it in the current window so you can watch the live log (Ctrl+C to stop). Best for the first test. |

Typical use: open the Copybara app on the iPad (Split View next to GoodNotes),
run **`start.bat`**, then copy on Windows and paste on the iPad. Check
**`status.bat`** anytime to confirm it's alive; **`stop.bat`** to end it.

Runtime files created in the folder: `copybara.pid`, `copybara.log`,
`copybara.err.log` (safe to delete when stopped).

### Notes

- It finds the iPad automatically via Bonjour. If discovery fails on a locked-down
  network, set `FALLBACK_HOST`/`FALLBACK_PORT` near the top of `copybara_win.py`
  (the iPad's Wi-Fi IP and the advertised port).
- Same iPad rule applies: clips are written only while Copybara is the active app
  (Split View).
- If `python` maps to the Microsoft Store stub, `setup.bat` falls back to `py`.
- Corporate app-allowlisting (AppLocker/WDAC) usually allows scripts run via your
  own Python; if a security tool blocks it, that's an IT policy, not a bug.
- The control scripts use inline PowerShell (`-Command`) for PID handling, which
  works under the default execution policy (no `.ps1` files are run).

## Weekly re-sign (free Apple ID)

When the iPad app stops launching (~7 days), re-run it from Xcode (⌘R with the
iPad connected) — ~30 seconds, your settings survive. To avoid this entirely:
- use a **paid Apple Developer account** ($99/yr → 1-year signing). Cleanest
  option, and safe on a work laptop (no extra tooling, no stored credentials
  beyond Xcode's own).
- **SideStore/AltStore** can auto-re-sign free-account apps over Wi-Fi, **but**
  they store your Apple ID credentials and install a background service / on-device
  VPN profile. Fine for a *personal* Mac; **avoid on a managed work laptop** — it
  can violate IT policy and trip endpoint security. Not recommended here.

## Project layout

```
copybara/
  mac/      macOS menu-bar agent (SwiftUI MenuBarExtra + Network + CryptoKit)
  ios/      iPad app (SwiftUI + Network listener + CryptoKit)
  windows/  Windows sender (Python: cryptography + pywin32 + pillow + zeroconf)
  scripts/  Mac login-item (LaunchAgent) install/uninstall
  docs/     protocol + design notes
```

Both sides share an identical `Protocol.swift` (service name, shared secret,
encryption, message shape). Messages are length-prefixed (4-byte big-endian
length + ChaChaPoly-encrypted JSON).

## Later: cross-network ("any Wi-Fi")

Add a small relay (a ~$5/mo VPS): the Mac and iPad each keep an outbound
connection to it and it forwards the encrypted blobs, so they no longer need to
be on the same LAN. The relay only ever sees ciphertext. (You'd still keep
Copybara in Split View on the iPad — the relay only changes *how the two devices
reach each other*, not the on-iPad paste behavior.)
